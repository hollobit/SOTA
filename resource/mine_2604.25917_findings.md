## Score extractions

STRICT ATTRIBUTION POSITION: Every row in Tables 2/3/6/7/8 either (a) names a multi-agent system / fine-tuned pipeline rather than a base-LLM (e.g., "RecursiveMAS", "Recursive-TextMAS", "MoA", "TextGrad", "LoopLM", "Single Agent w/ LoRA"), or (b) names an agent role in the paper's own system (e.g., "Expert Model", "Math Specialist") whose underlying LLM is identified in Table 1 but whose score reflects the in-paper fine-tuned/role-prompted variant, not the off-the-shelf base model.

The clearest case for registrable per-base-model scores is **Tables 6, 7, 8**, where the "individual agent" rows (Expert, Learner, Math Specialist, Code Specialist, Science Specialist, Reflector, Tool-Caller) correspond to a single, identified base LLM. However, the paper explicitly states (B.3) that for *every* agent in every pattern these models receive role-specific supervised training via inner-loop RecursiveLink. So even the "Expert" row is not raw Qwen3.5-9B but inner-link-warm-started Qwen3.5-9B. Calling it a "base-model evaluation" overstates what the paper measured.

Per the strict attribution rule (triple of model_name + benchmark_name + value with model_name being a canonical base model), I conservatively register only the cases where the paper explicitly labels the row with a model lineage AND the role is "single-agent" (i.e., not a multi-agent system, not a framework). I flag all such rows below; downstream curation can decide whether the inner-link warm-start disqualifies them.
